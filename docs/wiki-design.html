Summarizer Wiki: Blueprint

An agent-maintained wiki over every transcript and page in D1. First a one-time backfill, then a live update after each new summary, browsable in the dashboard and chattable. All of it runs on the existing summarizer Worker.

In short
  1. Claims are the atoms. Each source is turned into a card: claims with timestamps, entities and topics. Pages are written from claims, never straight from raw text.
  2. One Durable Object per wiki page (WikiPage) applies its edits one at a time. That lets ingest run in parallel without two agents clobbering the same page.
  3. The models make the calls (structure, merges, summaries, contradictions). Code checks the results: every link must resolve and every citation must name a real claim ID.
  4. Backfill and live updates share one ingest path. Backfill is a Workflow that pushes all 1,114 sources through the same queue a new summary uses.

Each component shows what it does, the Cloudflare primitive behind it, and the model it calls.

backfill One-time: 1,114 sources → a wiki on day one

1SegmentsRe-fetch timestamped captions for videos (laptop yt-summary.py, since YouTube blocks CF IPs) → POST /api/wiki/segments
2Fan-outWorkflow pages through D1 and enqueues 1,114 {sourceId} messages
3CardsThe queue consumer extracts claims, entities and topics as JSON-schema output. Runs in parallel.
4LibrarianOne big-context call reads all entity and topic names + counts and proposes the page plan, merges and splits
5Seed pagesFans out to WikiPage DOs. Each editor reads its claims and writes the page.
6IndexEmbed claims and pages into Vectorize, build FTS5, render index

The Workflow checkpoints every step and retries on its own. If the extractor fails on video 640, only that message gets redelivered. Unverified estimate: about 2–4 hours wall-clock at 8 consumers in parallel.

live On every new summary

1TriggerSummaryJob finishes → env.WIKI_INGEST.send({sourceId})
2CardSame extractor as backfill
3ResolveEach entity: Vectorize top-5 → LLM picks existing / new / unsure. Unsure → review queue
4RouteThe router agent picks which pages this source changes (often 3–8) → WikiPage.addClaims()
5DebounceThe page DO sets an alarm (10 min or 5 new claims) so 3 videos in a row become 1 rewrite
6Edit + validateThe editor rewrites the page. Code rejects unknown claim IDs or links, then saves a revision and re-embeds.

The extension panel gets a "Added to wiki: 4 pages" pill once step 6 lands.

gardeners Weekly, via Cron Trigger → Workflow

Merge proposer

Finds entity pairs that look alike (vector distance plus shared sources) and asks for a merge, with evidence.

Contradiction finder

Across each page's claims: "A says X (2025), B says not-X (2026)." Writes a disagreements box or a proposal.

Gap finder

Concepts mentioned in 3+ sources with no page → proposes a new page with its claim list.

Weekly digest

"What changed in your wiki": new pages, shifted consensus. Shown on the wiki home.

Gardeners never edit structure directly. They write proposals, and you approve or reject them in the Review queue. Low-risk changes (adding a citation, refreshing a summary) apply automatically.

query Chat

1AskFrom the wiki or any page ("ask about this page" pins it as context)
2SearchTool search_wiki: FTS5 + Vectorize hybrid over pages and claims
3ReadTools read_page, read_source(id, t) for the raw transcript window
4AnswerCites claim IDs, rendered as ▶ timestamp chips
5File back"Save as page" turns the answer into a proposal. Good answers become part of the wiki.

Validation code enforces (not the model)

  • Every [[claim:id]] in a page exists and belongs to that page's page_claims.
  • Every [[page:slug]] link resolves. Unknown links are stripped and logged as gap candidates.
  • A rewrite can't drop more than 30% of a page's citations without becoming a proposal.
  • Timestamps must fall within the source's duration.

Build order

  1. Migration + card extractor + queue; run it on 20 sources and check quality and cost.
  2. WikiPage DO + editor + validation; render /wiki/:slug.
  3. Backfill Workflow + librarian; run all 1,114.
  4. Hook SummaryJob → queue (live).
  5. WikiChat + review queue + gardeners. Put Access on /wiki before step 2 ships.

Open risk: timestamped segments. D1 stores flat text today. Without segments, citations stop at the video, not the moment. Backfilling segments needs the laptop native host, because YouTube blocks Cloudflare IPs.
